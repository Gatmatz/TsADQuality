Drawing The Line: Data Quality and Anomaly Detection In Time-series Data

A reproducible benchmark of how data-quality problems change what time-series anomaly detectors find
Code TSB-AD benchmark TSB-AD-U data

The six corruption types in the sweep, each applied by tsadquality with one of its swept settings to an excerpt of 339_UCR_id_37_Sensor from TSB-AD-U.

Overview

Anomaly-detection benchmarks score detectors on curated series, but data from real sensors and systems is rarely clean: it is noisy, it spikes, sensors freeze, samples arrive out of order. Drawing The Line measures how much each of these problems changes a detector's results, and why.

Every series in the TSB-AD-U evaluation set is corrupted in a controlled, reproducible way, at a range of severities. Each detector is then fitted and scored on both the clean and the corrupted series. Beyond accuracy metrics, the benchmark records a quantity from inside each fitted model, such as the k-distance gap of LOF or the nearest-neighbour distance gap of the matrix profile. This shows whether a drop in accuracy comes from anomalies looking less anomalous or from normal points looking more anomalous.

Results

Results will be published here once the full sweep has finished. For each detector and corruption, they will show how accuracy (e.g. VUS-PR, AUC-ROC) and the detector's internal separation change as the corruption gets more severe, relative to the same detector on the clean series.

Pipeline

  1. LoadA TSB-AD-U series and its precomputed window length and periodicity.
  2. CorruptInject one corruption at one setting with a fixed seed, or leave it clean.
  3. FitFit the detector with TSB-AD's implementation, keeping the fitted model.
  4. EvaluateScore it against the original labels, plus one internal metric from the model.
  5. StoreResults go to PostgreSQL; decision scores of clean runs to MinIO object storage.

Labels are never corrupted: a detector always sees the corrupted series but is scored against the original ground truth.

Corruptions

Every corruption is applied by an injector in tsadquality.corruption. The sweep covers every combination of the settings below. Spikes only hit normal points, since on anomalies they would make them easier to detect; every other corruption applies to the whole series.

Missing-value corruptions (point, burst and Gilbert–Elliott missingness) are implemented too, but are not part of the current sweep.

Evaluation

Accuracy

Every experiment is scored with TSB-AD's metrics: AUC-PR, AUC-ROC, VUS-PR, VUS-ROC, and the threshold-based Standard-F1, PA-F1, Event-based-F1, R-based-F1 and Affiliation-F. The threshold-based ones use a threshold a real deployment could use (mean + 2 standard deviations of the min-max-scaled scores), not the best possible threshold chosen with knowledge of the labels. The precision of that threshold is kept as well.

Internal metrics

Each detector also reports one quantity read from inside its fitted model (see the detector table). Per-window values are assigned to the centre point of their window, the same alignment TSB-AD uses for scores, and split by the point-level labels. Comparing a corrupted run with the clean run of the same series, seed and detector shows what the corruption changed inside the model.

Data

The benchmark uses the TSB-AD-U evaluation set, minus the 8 longest series (the MIT-BIH arrhythmia recordings and one UCR series, 500,000–900,000 points each), which would dominate the runtime. Series per source dataset:

Reproducibility

  • Every random step (corruption and detector) is seeded from one of three fixed seeds, and PyTorch runs in deterministic mode.
  • Each experiment has an ID that encodes the series, seed, corruption, every corruption setting and the detector. A run skips any experiment already stored.
  • The sweep can be split across parallel workers; each experiment is assigned to exactly one worker by a stable hash, whatever order they run in.
  • The detector code is a pinned copy of TSB-AD 1.5's wrappers, checked to produce identical scores.

Getting started

# install (Python 3.11, managed with uv)
uv sync

# configure credentials and the sweep, then start PostgreSQL and MinIO
cp .env.sample .env
docker compose up -d postgres minio

# download TSB-AD-U and precompute each series' window length and periodicity
uv run python tsadquality/data/download_tsb_ad_u.py
uv run python -m tsadquality.utils.ts_metadata_table

# run the sweep on N parallel workers
scripts/run_parallel_experiments.sh 18

# plot, e.g. accuracy against noise level for every detector
uv run python -m tsadquality.plots.WhiteNoiseLineplot --metric VUS-PR
